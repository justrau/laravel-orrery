# src/Runtime/

## The watcher and the breaker

- `Watcher::run($operation, $work, $default)` and `attempt()` run every package operation. They never rethrow into the host, except Laravel's `TimeoutExceededException`: with `Worker::$killOnTimeout` false the worker throws it into the running code, and it must reach the job (also through the wrapper of a `WatchesItself` listener).
- A dependency error (lost connection, SQLSTATE class `08`) of the **mirror's** session opens the mirror breaker for `observer.breaker_seconds` (30). While open, every watched operation is skipped and counted as dropped. Only the mirror's session opens it (`ErrorKinds::isMirrorDependency()`; also `MirrorRefused`, `SiblingFileUnavailable` and a `PooledSessionRefused` of the mirror's connection).
- **Lock timeouts**: two lock timeouts of mirror statements within `Watcher::MIRROR_TIMEOUT_WINDOW_SECONDS` (`ErrorKinds::isMirrorTimeout()`: MySQL and MariaDB 1205, Postgres `55P03`, SQLite busy or locked, and a `PackageTransactionBusy` of the mirror's session) open the breaker too; a success in between does not reset the count, because a lock on one table leaves the others writable. Statement timeouts (MySQL 3024, MariaDB 1969, Postgres `57014`) never count: MySQL's `max_execution_time` ends only reads. Such a breaker stays in its process (not shared) and stops only the flushes that are not terminating. The count lives per process, so under PHP-FPM a web request seldom reaches two.
- **A mirror session that cannot be built**: the watcher asks for the mirror session before each work; when that build throws a mirror dependency error (a pooled Postgres session connects in its build), the work fails with it and the breaker opens, so the next work does not connect again. The statements of a pooled build after its connect (the `search_path` read and the relation lookup) throw a `SessionPdoException` of the session, so a pooler without a backend opens the breaker too.
- **Across requests** (`SharedBreaker`): under PHP-FPM every request builds a new application, so a breaker that a mirror dependency error opened also goes into a small file per mirror (keyed per call by `PackageSession::mirrorKey()`) in `observer.shared_breaker_path` (default `storage/framework`). `observer.shared_breaker` null uses it outside the console only. While its breaker is closed, the watcher reads the file at most once per second (`Watcher::SHARED_READ_SECONDS`). The first reader of an end that passed, while the failure is recent, claims the probe: it moves the end `SharedBreaker::PROBE_SECONDS` ahead and tries the mirror itself (its own claim never holds it off); its success on the mirror removes the file, unless another process wrote a newer end meanwhile. An end beyond the breaker window (or `PROBE_SECONDS`, when that is longer) is ignored; a failed write is reported once per process (so once per request under PHP-FPM) and leaves no temporary file; the store never throws. Every degradation flush, the close's flush included, reads the file again first (`Watcher::skipsFlush()`). A flush whose write fails with a mirror dependency error opens and shares the breaker (`Watcher::flushFailed()`), so the work after the close of an expired breaker, and the next request after a terminating flush, do not connect again.
- A dependency error of another package session (a secondary queue database) is reported and handled per target: the runner defers that connection (`isBlockingFailure()`), and the measurement gives unknown rows (`UnreachableSecondaryTickTest`).
- `ErrorKinds::isDependency()`: a `QueryException` of a package session, or a `Storage\SessionPdoException` (a package session's PDOException that Laravel does not wrap). Any other PDOException names no session and stays a data error.
- Lost-connection texts are read only from the driver's error, never from a `QueryException`'s message, which holds the SQL with bindings (job text). The SQLSTATE comes from errorInfo, else the driver code, else the `SQLSTATE[xxxxx]` at the start of the message. On MySQL and MariaDB, client errors 2002, 2003, 2005, 2006, 2013 and 2055 count too, by number (macOS reports a connect timeout as `[2002] Operation timed out`, which is neither class `08` nor in Laravel's list).

## Reports carry no job value

- `Watcher::report()` reports a new `Exceptions\WatchedOperationFailed` with no previous exception and an empty trace. Match on its fields `operation`, `causeClass`, `sqlState`, `driverCode`, never on the message.
- The message is `SafeError::summary($operation, $problem)`, an allowlist: a `QueryException` gives class, SQLSTATE, driver code and the SQL template with `?` (never `getRawSql()` or bindings); the driver text stays only when it can hold no value. Another `Throwable` gives its class and the first line after `SafeError::strip()`. The summary is at most 2,000 bytes.
- `SafeText::clean()` cleans stored operator text such as the actor.

## Degradation and health events

- `Degradation` keeps one in-memory record per process: when the breaker opened, `dropped` (watched operations that were skipped or failed, not job observations one by one), `unmatched_observations`, `unverified`, `rollback_unverified` and the last error per operation. It flushes to `orrery_health_events`: workers at each throttled heartbeat, web requests and CLI commands at `terminating` (ObservationModule's callback, after the end of its unit of work; `orrery:tick` also flushes at its own end), every process when the breaker closes. A flush skips its write while a breaker that a mirror dependency error opened is open, here or in another process (`Watcher::skipsFlush()`); a flush that is not terminating (the heartbeat flush) also skips while a breaker of lock timeouts is open. A skipped terminating flush logs the record once; a terminating flush that writes gives the row its time as the end (the process ends with it), also when nothing changed since a flush wrote the row open, while the record in memory stays open, so a later event of a long-lived process opens the row again. The tick deletes closed windows past `health.retention_days`, and open windows whose start and last error are both older (a killed process).
- `GET /api/health` (`HealthController` documents each field) reports the windows, the tick, retention, the samples frontier, missing fence tables, uninstrumented connections, failed-record adapters, operations awaiting resolution, missing indexes, the schema version, SQLite warnings and more. A field that could not be read is null or `unreadable`, never zero. It always adds the notice "Unreported gaps cannot be ruled out.".

## Hooks

`Hooks::reach($point)` is a hold point for the process tests (see `tests/CLAUDE.md`). `Hooks::$callback` is a test seam, reset by `ResetsPackageState`.
